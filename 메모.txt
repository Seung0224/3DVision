#  1차: Timeout → 트리거 모드를 안 정해줘서 외부 트리거(인코더 등) 기다리다 실패로 추정, FreeRunning으로 명시 설정해서 해결 시도

# [캘리브레이션 데이터란]
#  - 센서 내부(레이저-카메라 사이 광학 기하구조)를 공장에서 개별 유닛마다 정밀 타겟으로 측정해서 만든 매핑 테이블. 센서 내장 메모리에 저장되어 출고됨.
#  - 우리가 설정한 게 아니라 하드웨어에 원래 딸려오는 공장 기본값. LoadCalibrationDataFromSensor()는 그걸 세션에 불러와 활성화하는 것뿐.
#  - 재캘리브레이션이 필요한 경우: 센서를 떨어뜨렸거나, 분해/재조립했거나, 레이저/카메라 모듈을 수리·교체했을 때 등 "물리적 광학 기준점"이 실제로 틀어졌을 때만. 보통 SmartRay 서비스센터에서 정밀 타겟으로 재수행.
#  - 센서 장착 각도(예: 45도 → 15도)를 바꾸는 것만으로는 재캘리브레이션 불필요. 대신 아래를 다시 맞춰야 함:
#     - SetTiltCorrectionPitch / SetTiltCorrectionYaw (장착 기울기를 알려줘서 좌표를 실제 세계 기준으로 보정)
#     - 노출 시간/레이저 세기 (각도 바뀌면 반사광량 달라짐)
#     - 측정 범위(FOV)가 바뀌므로 대상물이 유효 범위 안에 있는지 재확인
#     - 센서 로컬좌표 ↔ ACS 모터/작업 좌표계 정렬(핸드아이 캘리브레이션)은 SDK가 아니라 우리가 직접 관리해야 하는 별도 작업 (나중 단계)

# [무효 포인트 표시 방식]
#  - SmartRay는 측정 실패한 포인트를 NaN이 아니라 특수 상수값으로 표시함 (SDK 헤더 sr_api_defines.h 기준)
#    NONWORLDVALUE = -999997.0 / NONLUTVALUE = -999998.0 / BADWORLDVALUE = -999999.0
#  - 그래서 유효/무효 필터링할 때 NaN 체크만으로는 안 되고, -999990 이하 값도 무효로 걸러내야 함

# [진행 상황]
#  1단계-A: ACS 연결 + 상태 확인(읽기전용) - 완료
